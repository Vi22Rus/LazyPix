# AGENTS.md — правила работы с проектом LazyPix

> Утверждено пользователем 2026-11-23. Применяется ко всем новым задачам и веткам репозитория.

## 1. Репозиторий и компоненты

- Единственный репозиторий этого проекта: https://github.com/Vi22Rus/LazyPix ; основная ветка `main`. Не смешивать с отдельным проектом `Vi22Rus/LazyG`.
- Windows LazyPix: C# / .NET 10 / WPF, корневой `LazyPix.csproj`, `MainWindow.xaml(.cs)`, `Core/`, `Data/`, `Assets/`, `Localization/`.
- WoW Forever Lua-аддон: `LazyPix_Addon/`, `LazyPix_Addon.toc`, `Setup.lua`, `HealthWidget.lua`, `Circle*.tga`.
- Версии Windows и аддона вести отдельно. Номер `1.0.0` в csproj не равен подтверждённому релизу; версия аддона в main на дату утверждения — `0.8.30 TEST`.

## 2. Обязательное чтение перед работой

1. Полностью изучить `PROJECT_CONTEXT.md`, включая архитектуру и ограничения.
2. Проверить `HISTORY.md`: последние работы `LP-XXXX`, пользовательские тесты, известные ошибки и откаты.
3. Прочитать `CHANGELOG.md`: записи по коммитам и текущее состояние.
4. Получить реальные актуальные исходники именно выбранной ветки GitHub. Не восстанавливать код по памяти и не считать старый ZIP более актуальным, чем GitHub.
5. Для сборок проверить `.github/workflows/lazypix-windows-dev.yml`.

Если источник недоступен, сообщить прямо; не подменять его догадками.

## 3. Правила Git и безопасности изменений

- Никаких изменений кода, конфигурации, ресурсов и веток без прямого запроса пользователя.
- До правки установить исходную ветку и SHA, обозначить конкретные файлы, цель, риск и путь отката.
- Изменять строго указанную ветку. Экспериментальную ветку никогда не сливать в `main` без отдельного согласования; `main` не ломать ради эксперимента.
- Сохранять проверенные функции; не удалять соседние модули под видом очистки.
- Не переносить код и архитектуру между LazyPix и LazyG автоматически.
- Сторонние архивы/исходники/медиа публиковать только при наличии права на распространение.

## 4. Обязательная полная история — КАЖДЫЙ коммит с 2026-11-23

- **Каждый коммит на любой ветке**, включая docs-only, тесты, CI, ресурсы, обязательно отражать подробно в `CHANGELOG.md`. Нельзя писать только «исправления» или «улучшения».
- Для каждого коммита указать: дату и известное время с часовым поясом; SHA, ссылку и ветку; компонент и версии; **что сделано (точно, до/после)**; **где сделано (точные пути, функции/модули)**; **зачем сделано (проблема, запрос, ожидаемый результат)**; проверки и их результаты (включая «НЕ ПРОВЕРЕНО»); состояние теста пользователем; совместимость и откат.
- Если изменены несколько значимых механизмов/файлов — перечислить каждый отдельно и объяснить причину.
- `HISTORY.md` — главный подробный журнал анализа, хода работ, результатов и ошибок по формату `LP-XXXX` из `PROJECT_CONTEXT.md`. Каждый коммит должен иметь ссылку на относящуюся к нему работу `LP-XXXX` в `HISTORY.md`.
- `CHANGELOG.md` фиксирует фактические изменения по каждому коммиту (что/где/зачем), `HISTORY.md` — полную историю работы. Не допускать противоречий и не переписывать историю/даты задним числом.
- При необходимости отдельного документационного коммита явно связать SHA коммитов; по возможности включать документацию и код в один атомарный коммит.
- Вести отдельный статус Windows и Lua: ЗАПЛАНИРОВАНО, РЕАЛИЗОВАНО, CI PASS, ПРОВЕРЕНО ПОЛЬЗОВАТЕЛЕМ, НЕ ПРОВЕРЕНО, ОТКАТ.

## 5. Lua-аддон — обязательные инварианты

- Проверять актуальный `LazyPix_Addon/LazyPix_Addon.toc` (WoW Forever, `Interface: 16001` на момент утверждения).
- Имя папки `LazyPix_Addon`, TOC и пути текстур должны оставаться согласованными.
- Команда `/lazypix`; SavedVariables `SonahRotationSetupDB` сохранять для совместимости без согласованной миграции.
- `Setup.lua`: собственный фрейм, миникарта, режим предпросмотра, получение рекомендации. В main 0.8.30 имеются адаптеры Sonah, MaxDPS, Hekili, JustAC, RotationMaster; их наличие не доказывает работу в игре. В экспериментальных ветках адаптеры могут отличаться — проверять реальные исходники ветки.
- `HealthWidget.lua`: хилбот/индикатор здоровья и предметов, светофор, режимы и обработчики — не ломать при изменениях фрейма.
- Косметическая красная «змейка» рамки не влияет на доступность способности или RGB; приблизительное GCD-затемнение 1,5 с — отдельный механизм, не реальная гарантированная длительность GCD.
- WoW может возвращать `secret` значения. Не сравнивать, не форматировать и не выполнять арифметику с защищёнными значениями; `unknown` не трактовать как `false`.
- При изменениях проверять синтаксис Lua, `/reload`, предпросмотр книги заклинаний, миникарту/клики, показ/скрытие фрейма, GCD/CD/range/cast, светофор, хилбот и источники, на которые влияет изменение. Игровой тест не придумывать.

## 6. Windows-программа — обязательные инварианты

- `LazyPix.csproj` в корне; .NET 10 WPF, не .NET 8 из проекта LazyG.
- Сохранять профили/настройки/привязки. `%LOCALAPPDATA%\WoWForeverAssistant` и namespace `WoWForeverAssistant` — возможные ключи совместимости. Язык: `%APPDATA%\LazyPix\language.txt`.
- Не изменять G Hub, клавиатурный ввод и RGB-распознавание без проверки цепочки Lua-иконка → снимок → декодирование/сопоставление → разрешённое действие.
- При смене локализации/иконок проверять `Data/spells_ru_en.json`, `Localization/*.json` и ресурсы WPF.
- Команда PowerShell для single EXE из корня:
```powershell
dotnet publish LazyPix.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None
```
  Это инструкция, а не подтверждение успешной сборки.

## 7. Проверки, версии и выдача результата

- Для Windows: .NET 10 build/publish, GitHub Actions, конкретная ссылка на run и артефакт, smoke test и пользовательский запуск (отдельные статусы). При выдаче EXE приводить PowerShell-команду выше.
- Для аддона: синтаксис Lua (совместимая версия, по возможности 5.1), структура установки `Interface/AddOns/LazyPix_Addon/`, TOC, тест в WoW Forever и точка отката.
- `DEV` и `TEST` не объявлять релизами без подтверждения пользователя.
- При любом коммите обновлять `CHANGELOG.md` и `HISTORY.md`; указывать, что проверено, что нет, и следующие действия.
