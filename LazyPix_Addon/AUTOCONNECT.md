# LazyPix Auto Connect — 0.8.33-dev (эксперимент)

Три уровня соединения — **без пяти старых встроенных адаптеров**. Система не рассчитывает ротацию и не вызывает сторонние движки: читает только уже опубликованный результат. Без совместимого интерфейса рекомендацию получить нельзя.

1. **Обнаружение:** `Auto.Scan()` перечисляет загруженные аддоны через `C_AddOns` (или старый API); может прочитать `X-LazyPix-Provider` из TOC как путь к таблице с `read()`. Обнаружение аддона само по себе **не означает успешного подключения**.
2. **Универсальный интерфейс:** другой аддон может зарегистрировать источник после загрузки LazyPix:

```lua
LazyPixAutoConnect.RegisterProvider("MyRotation", {
    addon = "MyRotation",
    ready = function() return MyRotation.publicReady == true end,
    read = function()
        -- Только последняя опубликованная рекомендация!
        return MyRotation.publicIcon, MyRotation.publicSpellID
    end,
})
```

Также аддон может указать в своём TOC `## X-LazyPix-Provider: MyRotation.PublicBridge`, а `MyRotation.PublicBridge.read()` возвращает `texture, spellID`. Метаданные не создают API из ничего.

3. **Минимальный адаптер (без программирования в ядре):** в отдельном совместимом Lua-аддоне или дополнительном мосте вызвать:
```lua
LazyPixAutoConnect.RegisterAdapter("Example", {
    addon = "Example", path = "Example.Published.next",
    textureKey = "texture", spellKey = "spellID",
})
```
Мост работает **только** если этот путь содержит уже вычисленную рекомендацию. Он не угадывает иконку из произвольного чужого фрейма, не вызывает вычисление ротации. Для несовместимого аддона необходимо исследовать опубликованные поля и затем добавить этот конфигурационный вызов во внешнем модуле.

При ручном выборе идентификатор нечувствителен к регистру в команде WoW. Команды: `/lazypix sources` — список, `/lazypix source auto`, `/lazypix source <id>`, `/lazypix on` / `off` — предпросмотр. Иконка скрыта без рекомендации. При нескольких источниках автоматически выбирается доступный с большим `priority`, затем по имени; ручной выбор сохраняется.

**WoW Forever:** не сравнивать `secret`-значения. Защищённая текстура передаётся непосредственно UI API; защищённый SpellID считается неизвестным. `HealthWidget.lua` не затронут. Синтаксис Lua 5.1 и в игре не проверены на момент создания этой версии; необходимо проверить /reload, появление/исчезновение провайдера, выбор, preview, рамку, светофор и хилбот.

**Ограничение:** Реальные Sonah/MaxDPS/Hekili/JustAC/RotationMaster не подключатся без опубликованного совместимого интерфейса или отдельно созданного минимального моста. Их адаптеры в этой ветке не восстановлены.

## 0.8.33-dev — обезличенные стратегии P01–P05

Встроен `ProtocolDiscovery.lua`: проверка нескольких структурных признаков в опубликованных глобальных таблицах и реестре AceAddon, без имён конкретных сторонних продуктов в исполняемом коде. Один протокол соответствует одному прежнему способу чтения результата, но не назван его источником. P01 — Engine.Current + Listen + Registry.ActiveSpec; P02 — NextSpell + db.global + UpdateSpellFrame; P03 — Engine.Subscribe + Engine.Output.Primary + settings; P04 — mainFrame + spellIcons[1].iconTexture; P05 — nextWindow.frame + icons[1].texture + count.

Поддержка event-based P01 и passive subscription P03, периодический опрос P02/P04/P05. В случае более одного совпавшего объекта для протокола он отклоняется (`ambiguous`). Когда совпавший объект исчезает/меняется, ранее зарегистрированный источник временно выключается. Команда `/lazypix protocols` сообщает not-found / registered / ambiguous / lost / changed-source. Команда `/lazypix sources` по-прежнему показывает регистрацию.

**Ограничения:** распознавание структур не является доказательством конкретного продукта; случайные совпадения возможны. Пустая рекомендация вне боя не означает отсутствие протокола. P03 читает опубликованную очередь; без доступной текстуры этот источник может быть пуст. P04/P05 требуют созданной первой UI-иконки и видимого фрейма. Прямого сканирования произвольных UI-фреймов или вызова оценщиков ротации нет. Некоторые источники могут не экспортировать таблицу в `_G`/AceAddon — тогда они не обнаружатся. В WoW Forever не проверено; возврат к `0.8.32-dev` доступен по предыдущему SHA.

## 0.8.34-dev — LP-0015: исправление неполного обхода и диагностика P01–P05

**Игровой тест:** пользователь сообщил, что при включённом источнике P01 не подключился, а `/lazypix protocols` вывела `not-found` для всех пяти протоколов. Отсутствие рекомендации в этой ситуации объясняется тем, что до фазы чтения `Read()` протокол не дошёл.

**Обнаруженный дефект:** ранний обход `_G` в ProtocolDiscovery.lua искусственно прерывался после 12 000 записей, а Lua `pairs(_G)` не гарантирует порядок; полный глобальный объект мог быть пропущен. Дополнительно `field()` исключал `userdata`, что может мешать проверке UI-элементов. Эти изменения устраняют две возможные причины ложноотрицательного результата, но не доказывают, что именно они вызвали отказ в игре.

Теперь полный обход без произвольного лимита; диагностика выводит реальные подсчёты видимых признаков и лучший **единый объект** с максимальным числом совпавших признаков. Команда `/lazypix protocol debug` показывает статус и счётчики `Engine`, `Engine.Current`, `Listen`, `Registry.ActiveSpec` для P01, аналогично P02–P05. Сочетание разных признаков разных объектов не может активировать протокол. Диагностика не печатает идентификаторы сторонних аддонов и не вызывает их ротационные вычислители. Вводи команду вне боя, если диагностика вызывает лаги: полный обход больших Lua-глобалов имеет стоимость.

Новая mock-проверка воспроизводит P01 через обезличенную таблицу с точными интерфейсами. `0.8.34-dev` требует реального повторного теста в WoW Forever.


## 0.8.35-dev — LP-0017, срочное устранение регулярных лагов

**Реальный игровой тест пользователя (23.11.2026, 09:36:47 +07:00):** P01 `registered`, четыре признака YES, остальные P02–P05 `not-found`; нагрузка модификаций ~92%, фризы и ошибка Blizzard «Скрипт LazyPix_Addon превысил максимальное время работы», стек `[CAMERAORSELECTORMOVE]`. Стек не устанавливает точную горячую функцию.

**Подтверждённый недостаток кода:** `Auto.Tick` каждые две секунды выполнял `Auto.Scan` → `Protocol.Scan`, полный обход `_G`, 5 наборов диагностических проверок всех таблиц и 5 наборов проверки сигнатур. Полный поиск был намеренно снят с лимита в предыдущей версии, после чего стал особо дорогим. Невозможно доказать без профилировщика, что именно он давал все 92%, но систематическая тяжёлая работа подтверждена.

**Исправление:** при PLAYER_LOGIN одна первичная проверка; затем сканирование только после ADDON_LOADED, с объединением событий и ограничением частоты не чаще одного раза за 2 секунды. При отсутствии новых загрузок `Tick` не делает сканирования. `Protocol.Scan` выполняет дорогостоящий сбор независимых диагностических счётчиков только при `diagnostic=true`, который передаёт исключительно ручная команда `/lazypix protocol debug`. Команда `/lazypix protocols` показывает кешированные статусы без сканирования. Чтение уже найденной рекомендации остаётся периодическим, отдельно от обнаружения.

**Остаточный риск:** начальный одноразовый полный скан и ручной debug всё ещё способны дать паузу, особенно в окружении с большим числом таблиц. После появления нового аддона может быть повторный проход; без новых событий протоколы не обновляются автоматически. После обновления нужно проверить FPS, Lua CPU и отсутствие повторных таймаутов. Не возвращаться к 0.8.34-dev для живой игры: эта версия показала серьёзную проблему производительности.


## 0.8.36-dev — LP-0020: затемнение только от источника

Пользователь подтвердил подключение источников, но описал ложное затемнение GCD даже на способностях, не запускающих GCD. В предыдущем Setup.lua каждый успешный player cast начинал собственные 1,5 с GCD-затемнения и косметического таймера рамки, а RefreshVisuals также оценивал cooldown/range/cast независимо от материнского интерфейса. Это подтверждённая причина рассинхронизации.

Теперь LazyPix **не запускает собственный GCD и не рассчитывает самостоятельно доступность**. Опциональный третий результат Auto.Read(): dimmed=true/false/nil. Если состояние не опубликовано, иконка остаётся нейтральной (без придуманного затемнения). P01 читает опубликованные waiting/noPower/outOfRange с учётом showRangeTint, как в Sonah.zip/UI/Display.lua; P04/P05 пытаются прочесть GetDesaturation() из реально показанной текстуры источника. P02/P03 не имеют доказанного универсального пути к исходной затемнённости, поэтому ничего не выдумывают. Остальные свойства UI (cooldown swipe и прозрачность) не копируются. Декоративная рамка сохранена, но не запускается каждым кастом.

Совместимость: внешний RegisterProvider может по-прежнему возвращать два значения; third optional. Lua secret не сравниваются, неизвестное не считается false для игровой механики. **Возможен изменённый RGB-цвет фрейма** — Windows-связку обязательно проверить. CI и WoW тесты раздельны.


## 0.8.37-dev — LP-0022: обнаружение P03, P04, P05 без имён источников

**Новый тест пользователя для 0.8.36-dev:** P01/P02 обнаруживаются, P03/P04/P05 не обнаруживаются. P05 (старый адаптер окна preview) также не находил источник. Пользователь попросил исправить все три, не ломая работающие P01/P02 и не возвращая постоянное полное сканирование.

### Подтверждённые несоответствия с исходниками

- **P03:** проверял `t.settings` на корневом объекте; в предоставленном `Hekili_Forever.zip` `Engine.settings` создаётся в `Engine/Settings.lua`. И готовность нужно проверять по `Engine.settings.enabled`. `Engine.Subscribe` и `Engine.Output` присутствуют в `Engine/Output.lua`.
- **P04:** `LibStub` из `JustAC.zip/JustAC/Libs/LibStub/LibStub.lua` — вызываемая таблица (`setmetatable(LibStub,{__call=...})`), а не функция. Старый `enumerate()` пропускал реестр AceAddon `addons`. В `JustAC/UI/UIFrameFactory.lua` поля `mainFrame`, `spellIcons`, `iconTexture` создаются отдельными операциями, поэтому требовать первой иконки во время полного сканирования нельзя.
- **P05:** старый P05 проверял `nextWindow.icons[1]` и `count` уже при обнаружении. В актуальных исходниках `corporategoth/rotationmaster`, `UI/preview.lua`, окно публикуется как `addon.nextWindow`, первая иконка появляется лишь при `AddRecommendation`; функции `AddRecommendation`, `ReleaseChildren`, `Valid` существуют у созданного окна. Корневой объект `main.lua` экспортируется в глобальный реестр и содержит `GetPreviewArtChoices`. Изучался исходный код проекта, не переносился сторонний исходник.

### Реализация

В `ProtocolDiscovery.lua` протоколы P03/P04/P05 получили обновлённые структурные проверки, не использующие названия аддонов. P04 узнаётся по `mainFrame`, `spellIcons`, `GetProfile` и `UpdateFrameSize`; наличие/видимость первой иконки проверяется во время `Read()`. P05 узнаётся по `nextWindow.frame/icons` и методам `Valid/AddRecommendation/ReleaseChildren`; состояние активности и первой иконки проверяется во время `Read()`.

В начале полного поиска сохраняется **ограниченный список потенциальных владельцев UI** P04/P05. `AutoConnect.Tick()` не чаще одного раза в три секунды вызывает `Protocol.RefreshLate()`: проверяются только сохранённые корневые объекты, без `pairs(_G)`, без полного `Auto.Scan()` и без диагностических `report()`. Для позднего появления самого аддона остаётся событийная обработка `ADDON_LOADED`. При неоднозначности/смене уже зарегистрированного объекта остаются ограничения существующего `Scan()`. Если интерфейс не экспортирован в доступную таблицу, автоматическое подключение не гарантировано.

Новый `tests/protocol_recovery_test.lua` моделирует P03, табличный LibStub/AceAddon и UI P04/P05, появляющийся после первого сканирования, а также отсутствие полного скана при сотнях idle Tick. Добавлен в GitHub Actions для Lua 5.1.

**Риски:** одноразовый полный поиск всё ещё может нагружать клиент; частые полные проверки не возвращались. Наличие состояния `registered` не равно успешной демонстрации боевой рекомендации. Для P05 включи Preview Spells, иначе материнского окна с иконками может не быть. **0.8.37-dev пока не проверена пользователем в WoW Forever, не релиз.**


## 0.8.38-dev — LP-0024: серый слой от активного родительского кулдауна

**Отчёт пользователя:** в 0.8.37-dev подключение источников заработало, но собственная иконка LazyPix остаётся яркой, пока исходный фрейм показывает круговое восстановление способности. Пользователь попросил именно серое полупрозрачное покрытие в период кулдауна, автоматически исчезающее после его завершения, **без круговой анимации в LazyPix**.

**Реализация:** канал `Auto.Read()` расширен четвёртым необязательным значением `cooldownActive` (boolean/nil), не нарушая старый формат первых трёх. `Setup.lua` создаёт независимый полупрозрачный серо-чёрный слой поверх иконки, показывает его только при `cooldownActive == true`, убирает при `false` или неизвестном состоянии, при скрытии иконки, смене источника, а также в режиме настройки. Собственного GCD-таймера нет. Частота чтения рекомендации по-прежнему 0.2 с; новый глобальный поиск не добавлен.

**Как получаем достоверный признак:** для P01 через `UI.Display:Frames().icon.cooldown` (опубликованная структура из Sonah.zip/UI/Display.lua) и fallback `rec.waiting` только если parent-frame не выдал читаемый результат. Для P04 — из первого `spellIcons[1].cooldown`, подтверждённого JustAC.zip/JustAC/UI/UIFrameFactory.lua. У реального cooldown-виджета читается `IsShown()` и `GetCooldownTimes()`: начало/длительность в миллисекундах, сравниваются с `GetTime()` только если значения не `secret`. После истечения длительности значение становится false, серый слой исчезает. У P02/P03/P05 на данный момент нет подтверждённого единого безопасного интерфейса, позволяющего перенести **именно активное состояние родительского cooldown**; там остаётся нейтральная иконка или ранее поддержанное затемнение. Их отображение не объявляется синхронизированным. Нельзя считать отсутствие признака доказательством готовности способности.

**Границы:** активный GCD, если его действительно рисует исходный cooldown, также передаётся; не выдумывать GCD для off-GCD заклинаний. Если `GetCooldownTimes` возвращает защищённые поля (WoW Forever), программа не ветвится по ним и ничего не домысливает; источник может остаться нейтральным. Не копируется сама круговая анимация. Изменение яркости требует повторной проверки Windows RGB и любой пиксельной логики. Проверка сценариев active→expired добавлена в `protocol_recovery_test.lua`; реальное поведение в игре не подтверждено.
